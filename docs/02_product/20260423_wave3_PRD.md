## 0. Wave 3 願景（一句話）

> **讓 Wave 2 的 StockDetail 從「需要記得 stockId 才能用」的工具，進化成「打開 App 就有事可做」的日常陪伴型產品。**

對應的核心轉變：
- **Wave 2**：使用者必須「主動輸入 2330」→ 才能看到資料
- **Wave 3**：使用者「打開首頁」→ 看見自選股即時報價、收到價格警示推播、用中文「台積」就能搜到 2330

---

## 1. 背景與目標

### 1.1 背景

Wave 2 已交付 StockDetail 完整骨幹（即時報價、K 線、基本面、籌碼），但目前存在三個阻擋使用者「持續回訪」的關鍵缺口：

1. **入口缺口**：使用者必須直接輸入 stockId（例如 `2330`），不符合一般散戶記得「台積電」而非代號的習慣
2. **記憶缺口**：每次重新查詢都要重新輸入；沒有「我關心的這 5-10 檔股票」的概念
3. **觸達缺口**：使用者必須主動打開網站才能知道「股價變化」，無法在「達到關注價位時被提醒」

對照 MVP PRD §2.1 的主要 Persona「陳大明」的使用情境（早盤通勤 / 盤中午休 / 盤後研究），目前的 v0.2.0 只滿足「盤後研究」的一部分；早盤與盤中的「快速看一眼」與「重大事件提醒」完全沒有對應功能。

此外，Wave 2 移交 1 項 P0 與 17 項 P1 技術債，其中 **Spring Security（OWASP A01）必須在 Wave 3 完成**，否則無法進入滲透測試與 prod 上線階段。

### 1.2 目標

在「不擴大新功能廣度」的前提下，把現有 StockDetail **變成日常工具**：

1. **降低進入門檻**：中文 / 英文 / 代號模糊搜尋，3 個字元內找到目標股票
2. **建立回訪鉤子**：自選股（Watchlist）讓使用者「有理由打開」首頁
3. **建立主動觸達**：價格警示讓系統「主動找使用者」，而非只能等使用者來
4. **完成 Wave 2 安全債**：Spring Security 上線、滲透測試完成，達到對外公測門檻
5. **每個功能都 release-able**：即使 Wave 3 中途中斷，已完成的功能也能獨立發布

### 1.3 成功指標（North Star Metrics）

| 指標 | Wave 2 基準值 | Wave 3 目標值（上線後 4 週） | 量測方式 |
|------|---------------|------------------------------|----------|
| 註冊使用者次月留存率（M1 Retention） | 待測（v0.2.0 上線後量） | ≥ 40% | Cohort 分析 |
| 平均每使用者每日 StockDetail 開啟次數 | 待測 | ≥ 3 次 | 行為日誌 |
| 設定自選股的使用者比率 | 0%（功能不存在） | ≥ 60%（註冊後 7 日內） | 後台統計 |
| 啟用至少一條價格警示的使用者比率 | 0%（功能不存在） | ≥ 30% | 後台統計 |
| 透過搜尋進入 StockDetail 的比率 | 0%（無搜尋功能） | ≥ 70%（vs 直接輸入網址） | 行為日誌 |
| API P95 延遲（含新功能） | < 200ms | < 250ms | APM 監控 |
| OWASP ZAP 基線掃描 | 未執行 | 0 High / 0 Critical | 滲透測試報告 |

### 4.2 使用者故事（User Story）

#### F-W3-01：個股搜尋

##### US-W3-01-A：中文模糊搜尋

> **作為** 一位記得「台積電」但不記得代號 2330 的散戶，
> **我希望** 在搜尋框輸入「台積」就能看到「2330 台積電」的選項，
> **以便** 不需要 Google 查代號就能進入股票詳情頁。

**驗收條件（待 Peter 細化）**：
- 輸入 ≥ 1 字元即觸發搜尋（建議 debounce 250ms）
- 中文支援部分匹配（「台積」應命中「台積電」、「南亞科」搜「南亞」應命中「南亞」與「南亞科」）
- 英文 / 代號支援前綴匹配（「23」命中 `2301`、`2330`...）
- 結果列表顯示：代號、中文簡稱、所屬市場（上市/上櫃）
- 無結果時顯示「找不到符合的股票」（i18n）

##### US-W3-01-B：自動完成下拉

> **作為** 一位在手機上輸入較慢的使用者，
> **我希望** 看到下拉選單，可以用手指/鍵盤直接點選，
> **以便** 不需要打完整字串就能進入。

**驗收條件**：
- 結果最多顯示 10 筆
- 鍵盤上下鍵選擇 + Enter 進入
- 點選後直接導向 `/stocks/:stockId`

##### US-W3-01-C：熱門搜尋

> **作為** 一位剛打開首頁、還沒想好要看什麼的使用者，
> **我希望** 看到「現在大家都在搜什麼」，
> **以便** 獲得探索靈感。

**驗收條件**：
- 顯示前 10 名（依過去 24 小時搜尋次數，排除使用者自身）
- 熱門搜尋資料每小時更新
- **隱私要求**：熱門搜尋為彙總資料，不可暴露個別使用者搜尋紀錄

#### F-W3-02：自選股 Watchlist

##### US-W3-02-A：加入自選股

> **作為** 一位看完 StockDetail 的使用者，
> **我希望** 點一個按鈕就能把這檔加入我的自選股，
> **以便** 下次不用再搜尋。

**驗收條件**：
- StockDetail 頁面右上角加入「★ 加入自選股」按鈕
- 已在自選股的股票顯示「★ 已加入」（金色實心）
- 操作即時生效（樂觀更新 + 失敗回滾）
- **未登入使用者強制導向登入**（D-06 拍板：不提供匿名收藏 / localStorage 模式）：點擊按鈕跳出登入對話框，文案「登入即可跨裝置同步您的自選股」，登入完成後自動執行加入動作
- 自選股資料一律存後端（user_id 綁定），支援跨裝置同步

##### US-W3-02-B：首頁顯示自選股清單

> **作為** 一位早盤通勤的使用者，
> **我希望** 打開首頁就看到我 5-10 檔自選股的即時報價，
> **以便** 30 秒內掌握當日狀況。

**驗收條件**：
- 首頁取代目前的 placeholder
- 表格顯示：代號、名稱、現價、漲跌、漲跌幅、成交量
- 點任一列進入該股 StockDetail
- 空狀態（未加入任何自選股）：顯示引導 CTA「使用搜尋加入第一檔自選股」
- **效能**：10 檔自選股的彙整 API P95 < 500ms（避免 N+1）

##### US-W3-02-C：移除自選股

> **作為** 一位想清理列表的使用者，
> **我希望** 在自選股列表能直接移除股票，
> **以便** 不需要進入個股頁。

**驗收條件**：
- 列表每列右側有移除按鈕（垃圾桶圖示）
- 移除前彈出確認對話框（避免誤觸）
- 移除後即時更新列表

#### F-W3-03：價格警示 Price Alert

##### US-W3-03-A：設定突破價警示

> **作為** 一位希望在台積電跌破 580 元時收到提醒的使用者，
> **我希望** 在 StockDetail 設定「向下突破 580」警示，
> **以便** 不用一直盯盤。

**驗收條件**：
- StockDetail 頁面提供「設定警示」按鈕
- 警示類型：①向上突破指定價位 ②向下突破指定價位 ③日漲跌幅超過 X%
- 每個使用者每檔股票最多設定 5 條警示
- 警示觸發後自動標記為「已觸發」，不重複推播
- 使用者可在「我的警示」頁面管理（新增/啟用/停用/刪除）

##### US-W3-03-B：接收警示推播

> **作為** 設定了警示的使用者，
> **我希望** 警示觸發時能收到提醒，
> **以便** 即時做出反應。

**驗收條件**（D-07 拍板：**Web Push + Email**，LINE Notify 已 EOL 不採用，SMS 與 LINE Messaging API 延至 v1.0）：
- **推播管道**：
  - 主管道：**Web Push**（VAPID 協定，後端 Bruno 整合，前端 Felix 透過 Service Worker + Notification API）
  - 後援管道：**Email**（AWS SES），確保 iOS Safari 16.4 以下或未授權瀏覽器推播時仍能收到通知
- **使用者偏好**：Settings 頁可獨立開關 Web Push / Email 兩個管道（預設皆開）
- **送達 SLA**：觸發後 5 分鐘內送達（Web Push 通常 < 30 秒，Email 通常 < 2 分鐘）
- **推播內容**：股票名稱、觸發類型（突破上 / 下限 / 漲跌幅）、當前價格、觸發時間、深層連結
- **深層連結**：點擊推播 / Email 內按鈕可直接導向該股 StockDetail
- **降級處理**：若使用者瀏覽器拒絕 Web Push 權限，自動以 Email 為唯一管道並於 Settings 頁顯示「您的瀏覽器未授權 Web Push，已改用 Email」提示

##### US-W3-03-C：警示觸發判斷邏輯

> **作為** 系統，
> **我希望** 在每分鐘檢查一次價格警示，
> **以便** 在合理延遲內觸發。

**驗收條件**：
- 盤中（09:00-13:30 GMT+8）每分鐘檢查
- 盤後不檢查（節省資源）
- 假日不檢查（搭配 TD-7 交易日曆服務）

#### F-W3-04：Spring Security 上線 + 滲透測試（技術債清償）

> **作為** 平台營運方，
> **我們** 必須讓所有需要登入的 API 在未授權時回傳 401，
> **以便** 通過滲透測試並符合 OWASP A01 合規要求。

**驗收條件**（細節由 Sophia / Brian 設計）：
- 所有 `/api/v1/*` 端點（公開 API 除外）需 JWT 驗證
- **未授權請求一律回傳 HTTP 200 + envelope `code: 3001`**（D-08 拍板，**不使用 HTTP 401**），符合 [api-design.md](../../.claude/rules/api-design.md) Envelope Pattern
- Spring Security 必須客製 `AuthenticationEntryPoint` 與 `AccessDeniedHandler`，覆蓋預設 401 / 403 行為，回傳統一 envelope 結構
- envelope 欄位需含：`code: 3001`、`message: "未登入"`、`timestamp`、`traceId`
- 前端 axios 攔截器偵測到 `code: 3001` 時導向登入頁（Felix 負責）
- 通過 OWASP ZAP 基線掃描（0 High / 0 Critical）
- 第三方滲透測試廠商簽核報告（廠商選定見決策紀錄 D-02 / D-09，⏸ 保留待使用者親簽）
- 滲透測試報告須附註說明：未授權回 HTTP 200 + code 3001 為設計決策，非漏洞

#### F-W3-05：搜尋歷史紀錄

##### US-W3-05-A：顯示最近搜尋

> **作為** 一位常查同樣幾檔股票的使用者，
> **我希望** 點開搜尋框就看到我最近搜過的 10 檔，
> **以便** 不用重複輸入。

**驗收條件**：
- 搜尋框 focus 但未輸入時顯示「最近搜尋」
- 顯示最多 10 筆，依時間降序
- 每筆右側有 X 可移除單筆
- 「清除全部」按鈕
- **儲存位置**：D-06 拍板「強制登入」原則一致，**搜尋歷史一律存後端**（user_id 綁定），支援跨裝置同步
- 未登入使用者：搜尋框 focus 不顯示歷史區塊，僅顯示熱門搜尋（避免 localStorage 雙軌邏輯）

## 5. 使用者旅程

### 5.1 Happy Path：「我是台股新手，剛使用 v0.2.0」的使用者

```
Day 0（v0.2.0 上線時的舊體驗）
─────────────────────────────────
```

### 5.2 Edge Cases

| 情境 | 預期行為 |
|------|----------|
| 搜尋無結果（例如輸入「abcdef」） | 顯示「找不到符合的股票」+ i18n + 引導去看熱門搜尋 |

| 警示設定價位明顯不合理（如台積電設 1 元觸發） | 不阻擋（使用者自由），但 UI 提示「此價位距離當前 XX%」 |
| 警示觸發時使用者瀏覽器未開啟 | Web Push 進入作業系統通知中心；Email 進信箱 |
| 推播管道全部失敗 | 後台日誌記錄，不重試（避免延遲累積）；下次觸發再試 |
| 未登入使用者點「加入自選股」 | 跳出登入對話框（D-06 強制登入），文案「登入即可跨裝置同步您的自選股」+ 紀錄「登入後執行」意圖（登入完成自動補做加入動作） |

### D-08（原 D4）：未授權回傳 HTTP 200 + Envelope code 3001 — ✅ 已拍板

- **拍板結果**：**HTTP 200 + envelope `code: 3001`**，**不使用 HTTP 401**
- **理由摘要**：①完全符合現有 [api-design.md](../../.claude/rules/api-design.md) Envelope Pattern ②統一前端錯誤處理（一律從 envelope.code 判斷）③避免某些 proxy / firewall 對 401 特殊處理
- **實作要求**：
  - Bruno：Spring Security 客製 `AuthenticationEntryPoint` 與 `AccessDeniedHandler`，覆蓋預設 401 / 403 行為
  - Felix：axios interceptor 偵測到 `code: 3001` 時清空 token 並導向登入頁
- **滲透測試溝通**：報告須附註說明「未授權回 HTTP 200 + code 3001 為設計決策，非漏洞」
- **影響範圍**：§4.2 F-W3-04、§5.2 Edge Cases

### 8.1 限制

- **股票主檔資料來源**：依賴 Wave 2 已建立的 `stock_info` 表；若主檔不全（特別是 OTC 股票），搜尋結果會缺失（呼應 TD-6 Wave 2）

## 13. Peter 接手指引（SRS 應重點細化的 5 個項目）

PRD 已定稿並對齊拍板決策，Peter 接手 SRS（系統需求規格）時，請特別針對以下 5 個項目做深度細化，避免 Sophia / Preston / Bruno / Felix 接手時還需回頭問 PM：

### 13.1 Spring Security 統一 envelope 401 → 200 + code 3001 的端到端契約

- **後端契約**：列出 `AuthenticationEntryPoint` 與 `AccessDeniedHandler` 回傳的完整 envelope JSON（`code` / `message` / `timestamp` / `traceId` 欄位定義 + 範例）
- **觸發場景矩陣**：未帶 token、token 過期、token 簽章錯誤、token 黑名單命中（搭配 TD-1）→ 各自對應的 message 文案與是否需 audit log
- **前端契約**：axios interceptor 偵測 `code: 3001` 後的處理流程（清空 token、儲存 returnUrl、導向 /login）
- **公開 API 白名單**：明確列出哪些 endpoint 不需 JWT 驗證（如 `/api/v1/auth/login`、`/api/v1/stock/search` 部分）

### 13.2 Watchlist 強制登入流程的「登入後自動補做」UX 規格

- **意圖暫存機制**：未登入點擊「★ 加入自選股」時，前端如何暫存意圖（建議 sessionStorage + 過期 5 分鐘）
- **登入完成後的觸發點**：登入成功 callback 偵測到暫存意圖時，自動呼叫加入 API + Toast 提示「已加入自選股」
- **失敗處理**：若登入後 stockId 已不存在或加入失敗，提示但不阻擋
- **API Spec**：`POST /api/v1/watchlist/add` 的 request / response / 錯誤碼定義（含「已加入過」「已達 50 檔上限」）

### 13.3 Web Push + Email 雙管道推播的偏好與降級規格

- **使用者偏好設定**：`POST /api/v1/user/notification-preference` API（欄位：webPushEnabled / emailEnabled / 各管道訂閱主題）
- **VAPID 金鑰管理**：後端如何產生與儲存 VAPID public/private key、前端如何訂閱 push subscription
- **降級判定邏輯**：何時自動退回 Email（無 push subscription / 推送失敗 N 次 / 使用者主動關閉）
- **送達追蹤**：是否記錄送達狀態（建議 audit_log 寫入 `notification_log` 表）
- **Email 模板**：設定觸發 email 主旨與 HTML 模板規格（含深層連結 + i18n）

### 13.4 價格警示觸發引擎的時序與 idempotency 規格

- **檢查排程**：盤中（09:00-13:30 GMT+8）每分鐘檢查的 cron 表達式 + Spring `@Scheduled` 設計
