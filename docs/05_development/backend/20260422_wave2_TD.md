## 已修復（Wave 2 處理）

### TD-2：Spring Security JWT 正規化

**來源**：Brian 審查報告（Wave 1）

**問題**：`MemberController` 直接依賴 `io.jsonwebtoken.ExpiredJwtException`、`io.jsonwebtoken.JwtException`，違反層間封裝原則，若更換 JWT 實作庫需改動 Controller。

**修正**：
- 建立 `JwtAuthException`（sealed abstract）+ `JwtExpiredException` + `JwtInvalidException`
- `JwtTokenProvider.parse()` 統一捕獲並包裝為自家例外
- Controller 改為 catch `JwtAuthException`，消除對 jjwt API 的直接依賴
- 更新 `JwtTokenProviderTest`，驗證三種失效情境均拋自家例外

**影響範圍**：`stock-member` 模組

## 新增（Wave 2 產生的 TD，留後處理）

### TD-3：MOPS 半公開 API 穩定性風險

**描述**：`MOPSClientImpl` 呼叫 MOPS `ajax_t163sb04` / `ajax_t163sb05`，這是非正式 JSON endpoint，官方可能無預告更改。

**風險等級**：中
**建議**：Wave 3 評估替代方案（券商 API、FinMind 第三方平台），或建立 API 健康監控 Alert。

---

### TD-4：listQuotes 外部 fallback 串行問題

**描述**：`QuoteServiceImpl.listQuotes()` 對於 DB miss 的股票，目前在 for loop 中逐一呼叫外部 Client，若 miss 的股票多則耗時累加。

**風險等級**：低（TWSE 每次回傳全市場，實際上不會多次呼叫）
**建議**：Wave 3 改用 Virtual Thread 批次或整批抓取後過濾。

---

### TD-5：Redis 快取 Namespace 缺失

**描述**：Redis key 無環境前綴（如 `dev:quote:2330:daily`），若 dev/uat 共用 Redis 會互相污染。

**風險等級**：低（目前各環境 Redis 獨立）
**建議**：加入 `stock.cache.key-prefix` 設定，ServiceImpl 組 key 時拼入前綴。

---

### TD-6：M-CHIP 模組缺 OTC 籌碼支援

**描述**：`ChipServiceImpl` 僅串 TWSE 三大法人，OTC（上櫃）股票籌碼無資料。

**風險等級**：中
**建議**：Wave 3 補充 OTC 籌碼 Client（TPEX 提供相應端點），`ChipService.getChip()` 依市場別分流。
