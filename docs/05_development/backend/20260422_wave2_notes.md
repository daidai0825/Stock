## 一、TD-2 修正：JWT 例外封裝

### 問題

Wave 1 `MemberController.currentUserId()` 直接 catch `io.jsonwebtoken.ExpiredJwtException`，將 jjwt 實作細節洩漏到 Controller 層。

### 修正方式

建立 `sealed` 例外層次：

```
JwtAuthException (sealed abstract)
├── JwtExpiredException  → 3002 TOKEN_EXPIRED
└── JwtInvalidException  → 3003 TOKEN_INVALID
```

`JwtTokenProvider.parse()` 統一捕獲 jjwt 例外後重新包裝為自家類別。Controller 只需 catch `JwtAuthException`，未來換掉 jjwt 不影響上層。

**設計決策**：用 `sealed` 而非普通繼承，確保 `JwtAuthException` 的子類別只有這兩種（Pattern matching 可窮舉）。

## 二、外部 Client 基礎設施設計

### RestClient 設定（Spring 6）

- 每個 Client（TWSE / OTC / MOPS）各自持有獨立的 `RestClient` bean，以 `@Qualifier` 注入
- connect 3s / read 10s（`SimpleClientHttpRequestFactory`）
- Base URL 固定寫在設定檔，**不接受使用者輸入動態組成**（SSRF 防護）

### 重試策略（@Retryable）

- `maxAttempts = 3`，指數退避 1s → 2s → 4s
- 只對 `RestClientException`（網路失敗）和 `ExternalServiceException` 重試
- `InfrastructureAutoConfig` 加 `@EnableRetry` 啟用

### 日誌策略

每次呼叫記錄：`endpoint + traceId + 耗時（ms）`，**不記錄回應內容**（避免大量資料污染 log，也避免洩漏潛在敏感欄位）。

### 例外轉換

所有 Client 失敗統一包裝為 `ExternalServiceException(5xxx)`，`GlobalExceptionHandler` 攔截後回 HTTP 200 + 業務碼。

### TWSE 民國年轉換

TWSE 部分 API 使用民國年（`113/01/02`），Client Impl 內部轉換為西元年（`2024/01/02`），對外一律暴露 `LocalDate`（西元）。

## 三、Redis 快取策略

| 模組 | Key 格式 | TTL（盤中） | TTL（盤後/固定） |
|------|----------|-------------|------------------|
| M-QUOTE | `quote:{stockId}:daily` | 30s | 1h |
| M-QUOTE history | `quote:{stockId}:history:{yyyy-M}` | - | 1h |
| M-FUND | `fundamental:{stockId}` | - | 24h |
| M-CHIP | `chip:{stockId}:daily` | - | 24h |

**盤中判斷**：依台灣 `Asia/Taipei` 時區，09:00–14:30 為盤中。

**快取序列化**：沿用 Wave 1 的 `RedisConfig`（`GenericJackson2JsonRedisSerializer` + JavaTimeModule），`LocalDate` / `LocalDateTime` 正確序列化。

## 四、M-QUOTE 設計決策

### 批次查詢（listQuotes）

策略：先批次 Redis cache lookup → DB `DISTINCT ON (stock_id) ORDER BY stock_id, quote_date DESC`（避免 N+1）→ 仍有 miss 的股票再分別呼叫外部 Client。

**N+1 風險點**：「仍 miss 的股票各自呼叫外部 Client」存在多次呼叫，但因 TWSE 每次傳回全市場行情，實際上第一次呼叫就能取得所有 TWSE 股票，第二次呼叫 OTC。可在後續 Wave 優化為批次抓取後分散。

### Upsert 策略

PostgreSQL `ON CONFLICT (stock_id, quote_date) DO UPDATE`，保冪等性，重跑不會有重複資料。

### XML Mapper

`findLatestByStockIds` 使用動態 `<foreach>` IN 子句（XML），避免 MyBatis 的 `ANY(array[])` TypeHandler 複雜性。

## 五、M-FUND 設計決策

MOPS API 未提供正式公開 JSON endpoint，此處呼叫其半公開 JSON endpoint（`ajax_t163sb04`、`ajax_t163sb05`）。若官方 API 格式異動，需同步更新 `MOPSClientImpl` 解析邏輯。

**近四季 EPS 計算**：取 MOPS 回傳的 EPS 清單，排序後取最新 4 筆加總，存入 `stock_fundamental.eps`。

## 六、資料庫 Migration

Flyway `V2.0.0__create_quote_fundamental_chip_tables.sql` 建立三張表：
- `stock_quote`：唯一索引 `(stock_id, quote_date)`，支援 Upsert
- `stock_fundamental`：唯一索引 `(stock_id)`，一檔股票只保留最新一筆
- `stock_chip`：唯一索引 `(stock_id, trade_date)`，支援 Upsert
