## 議題 1：AI 模組合規定位

- **議題**：「AI 綜合評分 + 買賣訊號」是否會被金管會認定為投資顧問業務？
- **方案 A**：先諮詢律師再決定
- **方案 B**：改為純資訊呈現（無「建議買入/賣出」字眼） ✅ **採納**
- **方案 C**：接受風險照原計畫做

### 最終決定：**方案 B**

**理由**：
- 法律風險最低，無需等律師延誤時程
- 仍保留 AI 差異化（綜合評分、訊號摘要可呈現，但措辭調整）
- 後續若取得執照可再升級為「建議」型產品

### 落實要求

| 項目 | 調整方向 |
|------|----------|
| 「綜合評分」 | 維持，但定位為「個股健康度指標」 |
| 「買賣訊號摘要」 | 改為「技術型態觀察」「籌碼動向觀察」 |
| 「個人化警示」 | 改為「條件達成提醒」（使用者自設條件） |
| 所有 UI 文案 | 禁用「建議買入」「建議賣出」「應該」「最佳」等字眼 |
| 必加聲明 | 「本平台僅供資訊參考，不構成投資建議。投資有風險，請審慎評估。」 |

### 影響範圍

- PRD 第 3.6 節（AI 評分）需修訂措辭
- Peter 撰寫 SRS 時需明列文案規範
- 前端開發（Felix）需建立 i18n 文案庫並由法務複核
- QA（Quincy/Quinn）需新增「合規文案檢查」測試案例

## 議題 2：部署架構

- **議題**：PROJECT.md 寫「AWS + 地端」，地端是否必要？
- **方案 A**：純 AWS
- **方案 B**：純地端
- **方案 C**：AWS + 地端混合 ✅ **採納**

### 最終決定：**方案 C**

**理由**：
- 使用者明確要求保留「AWS + 地端」原規劃
- 接受成本與時程的代價（與 Q3-B 配套）

### 落實要求

| 項目 | 設計方向 |
|------|----------|
| AWS 角色 | 主要對外服務、CDN、推播、AI 計算 |
| 地端角色 | 待定（由 Sophia 評估：DB 主庫？敏感資料儲存？備援？） |
| 資料同步 | 必須設計 AWS ↔ 地端同步機制 |
| DR（災難復原） | 雙環境互為備援 |
| CI/CD | Jenkins 需同時支援 AWS + 地端部署管線 |

### 影響範圍

- Sophia 必須產出兩份部署架構圖（AWS / 地端）+ 同步策略
- Preston 需考量地端硬體規格與機房需求
- DevOps 成本預估翻倍
- 上線時程預估順延 4-6 週

## 議題 3：MVP 範圍與時程

- **議題**：30 項 P0 功能能否在 Q3 2026 完成？
- **方案 A**：分批上線（v1 縮減 + v1.1 補完）
- **方案 B**：全做，時程延至 Q4 2026 ✅ **採納**

### 最終決定：**方案 B**

**理由**：
- 使用者堅持「提出的功能都必須做到」
- 接受時程延後

### 落實要求

| 項目 | 內容 |
